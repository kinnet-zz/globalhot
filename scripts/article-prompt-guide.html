1. 수동 작성 프롬프트 구조

이번 2편은 AI 없이 수동으로 작성했습니다. 다음 기준으로 주제를 선정하고 내용을 구성했습니다.

주제 선정 기준

  • 기존 카테고리와 중복 배제 — 기술·AI, 과학·기술, 비즈니스·문화 등 기존 8개 카테고리와 겹치지 않도록 선택
  • 2026년 트렌드 반영 — 글로벌 미디어에서 올해 활발히 다뤄지는 화제
  • 한국적 시각 포함 — 글로벌 이슈에 한국의 현황이나 시사점을 연결

작성 순서

  1. 기존 아티클 HTML 구조 분석 (style.css, post-nav, disclaimer 등)
  2. 제목(25-45자), 부제(50-90자), 태그(4-5개) 기획
  3. 본문 600-900자 Korean HTML 작성 (h2 단위 섹션, blockquote, ul 포함)
  4. 파일명 slug 생성 (영문 소문자 + 하이픈)
  5. posts/index.html에 항목 추가
  6. 이전 글/다음 글 네비게이션 체인 연결

2. AI 자동 생성 (write.ps1)

write.ps1 스크립트는 OpenRouter 또는 OpenCode API를 통해 AI로 아티클을 자동 생성합니다.

실행 명령어

# PowerShell
$env:OPENROUTER2 = "sk-or-v1-..."
.\write.ps1 -Topic "주제" -Category "카테고리" -Provider openrouter -Model "openai/gpt-4o-mini"
파라미터기본값설명
-Topic(필수)아티클 주제 (예: "양자 컴퓨터 상용화")
-Category"기술"표시용 카테고리명
-Provider"openrouter"openrouter 또는 opencode
-Model"openai/gpt-4o-mini"사용할 AI 모델

3. 시스템 프롬프트

write.ps1이 AI에 전송하는 실제 프롬프트입니다.

System Message

You are a professional Korean journalist.
Return ONLY valid JSON in Korean.
No markdown fences.

User Message (템플릿)

Write a Korean curation article about '{Topic}' in category '{Category}'.
Return JSON:

{
  "title": "25-45자 제목",
  "subtitle": "50-90자 요약",
  "tags": ["태그1", "태그2", "태그3", "태그4"],
  "body_html": "<h2>...</h2><p>...</p>"
}

Body: 600-900 words in Korean HTML.
Include real 2026 trends, companies, Korea angle.

프롬프트 설계 의도

  • JSON 강제 — HTML 파일 생성을 위해 구조화된 데이터 필요
  • Markdown fence 금지 — ```json 블록이 포함되면 파싱 실패
  • 한국어 전용 — 큐레이션 사이트의 언어 통일성 유지
  • 2026 트렌드 + 실제 기업명 — AI 환각을 줄이고 신뢰도 확보
  • Korea angle — 글로벌 이슈에 한국 독자를 위한 접점 제공

4. 아티클 구조 템플릿

모든 아티클은 다음 HTML 구조를 따릅니다.

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width" />
  <script src="/analytics.js"></script>
  <meta name="description" content="..." />
  <title>제목 | Global Hot Reads</title>
  <link rel="canonical" href="..." />
  <link rel="stylesheet" href="/style.css" />
  ...
</head>
<body class="post-page">
  <header class="header">...</header>
  <main class="post-wrap">
    <p class="post-category">카테고리 · 주제</p>
    <h1>제목</h1>
    <p class="post-meta">날짜 · 거리의악사</p>
    <p class="post-subtitle">부제</p>
    <div class="post-body">
      <p>본문...</p>
      <h2>섹션 제목</h2>
      <p>...</p>
      <blockquote>인용</blockquote>
      <ul><li>...</li></ul>
    </div>
    <div class="post-footer">
      <div class="post-tags">...</div>
    </div>
    <div class="post-nav">
      <a href="...">← 이전 글</a>
      <a href="...">다음 글 →</a>
    </div>
    <div class="disclaimer">...</div>
  </main>
  <footer class="site-footer">...</footer>
</body>
</html>
참고: style.css?v=20260718-4는 캐시 버스터링을 위한 버전 파라미터입니다. 스타일 변경 시 숫자를 업데이트하세요.

5. QA 체크리스트

아티클 생성 후 검증해야 할 항목입니다.

항목확인
파일명 slug 중복 여부posts/ 내 동일 파일명 존재 확인
canonical URL 일치파일명과 link rel="canonical" 일치
네비게이션 체인이전 글/다음 글 순서가 시간순으로 연결됨
posts/index.html 업데이트최신 글이 목록 상단에 추가됨
카테고리 태그 일관성기존 카테고리명과 포맷 통일 (예: "과학 · 기술")
HTML 문법 검증닫힘 태그, 따옴표 누락 여부
특수문자 인코딩한글 파일명 URL 인코딩 확인 (특히 index.html 링크)
